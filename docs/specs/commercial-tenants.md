# テナント契約（共有インスタンス上の契約者分離）

ステータス: **実装済み（2026-08-24）**  
対象: 共有 `sa2-plus.com` 上で、契約者ごとにユーザー・鍵・休日を分ける

関連:

- `docs/specs/commercial-public-readiness.md` … 販売方針の親メモ
- `docs/specs/commercial-storage.md` … ストレージ接続
- `docs/specs/commercial-usage-limits.md` … 運営キー利用時の契約プール上限
- `docs/specs/commercial-dedicated-instance.md` … 別サーバーの専用インスタンス（販路 A）

## 売り物

**契約者（テナント）** は今の「管理者ロール」ではない。ユーザーがその契約に所属する箱である。

| 段階 | 対象 | どこ | 管理者 | 鍵 |
|---|---|---|---|---|
| 1. Light / Standard | 個人 | 共有サーバー | なし（`tenant_id` なし） | 運営（プラットフォーム） |
| 2. テナント契約 | 家庭・小規模の代表 | **同じ共有サーバー** | 契約代表（Admin）**1名だけ**（自分の契約の中） | 代表が R2／B2／AI／API を設定。未設定なら運営キーにフォールバック |
| 3. 専用インスタンス | サーバーごと分けたい組織 | 別サーバー | 契約代表 | インスタンス全体が1顧客。テナント表は使わなくてよい |

## パッケージ（専用インスタンスと同じ中身）

公開料金（税別・`config/commercial.php`）。TOP に出す。

| 項目 | テナント契約 | 専用インスタンス |
|---|---|---|
| 試用 | **最初の 30 日は月額なし** | 個別見積 |
| 月額 | **¥3,980**（5名・メール各1込み） | ¥8,000〜（5名まで。メールはオプション） |
| 年額 | 月額 × 11か月分 | 同左の割引 |
| 管理者 | 契約代表 **1名**。追加は Standard / Light。2人目の Admin は作れない | 同じ |
| ユーザー | 月 **5名まで**（代表を含む）。初期 `max_users` は `commercial.included_users` | 同じ |
| `@sa2-plus.com` | 所属ユーザー **各1アドレス込み**（Light でも可。申請→運営が手作成） | **オプション**（¥300／月） |
| 6人目以降 | 運営 SuperAdmin が `max_users` を上げる（目安 ¥1,000／人／月） | 同じ目安 |
| サーバー | 共有 `sa2-plus.com`（DB 同居） | 別サーバー |

専用の見積（初期 ¥50,000、月額 ¥8,000、メールオプション）は変えない。詳細の製品方針は `docs/specs/product-direction.md`。

## できないこと（今もやらない）

- 契約者に **LINE 公式アカウント／Web Push VAPID／招待コード／鮮明化** を渡す（ドメイン・Webhook・試作の都合で運営専用）
- 48 テーブル全部へ `tenant_id` を足すこと。ToDo・写真などは従来どおり `user_id`。所属ユーザーが見えなければ他契約のデータには届かない
- 専用インスタンスの代わりにすること。データは同じ DB に同居する。サーバー分離が必要なら販路 A

## データ

- `tenants` … 契約。`status`（active / suspended）、`max_users`、`allow_own_keys`、`owner_user_id`、`trial_ends_at`（試用終了日。空は本契約。切れても自動停止しない）
- `users.tenant_id` … 所属。null は個人プランまたは運営スタッフ
- `media_storage_settings.tenant_scope` … `COALESCE(tenant_id, 0)`。0 が運営キー
- `translation_api_keys.tenant_scope` … DeepL キーも契約ごと
- `holiday_entries` / `weekday_rules` の `tenant_id` … 管理者画面の休日は契約ごと（個人休日は `user_id`）

運営 SuperAdmin のコンテキストは常にプラットフォーム（`tenant_id` なし）。契約代表でログインするとその契約のキーが使われる。

## 権限

| 操作 | SuperAdmin | テナント Admin | プラットフォーム Admin（`tenant_id` なし・専用インスタンス向け） |
|---|---|---|---|
| テナント契約の作成 | 可 | 不可 | 不可 |
| ユーザー一覧 | 全員 | 自分の契約だけ | `tenant_id` なしのユーザーだけ |
| 契約内の Admin 追加 | 代表の維持のみ | **不可**（代表1名） | 専用運用の代表1名 |
| ストレージ／LLM／Maps 等 | 運営キー | 自分の契約のキー | 運営キー（インスタンス全体） |
| 招待コード・メール申請の承認・ストレージ監視 | 可 | 不可 | 可（専用運用） |

## フォールバック

契約がストレージや AI をまだ保存していないあいだは、運営のキーを使う。保存して有効化するかシークレットを入れると、その契約だけ切り替わる。
