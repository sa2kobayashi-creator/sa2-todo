## 1. 売り物の一言

**「家族・小組織向けの Todo／メモ／写真／メッセージ／メールを、顧客専用の環境で提供する」**

容量課金を看板にしない。売りは次の3点。

1. データと設定が他顧客と同居しない（専用インスタンス）
2. ストレージや API キーは顧客持ちにできる（BYOK → 従量原価を顧客側へ）
3. `@sa2-plus.com` メールはオプションで足せる（既存申請フロー）

## 3. 含まれるもの／含まれないもの

### 含まれる（標準）

- 専用のアプリ一式（Laravel）と DB
- HTTPS 公開（顧客ドメインまたはサブドメイン）
- 契約代表用 **Admin** 1名、追加ユーザーは Standard / Light
- Todo / メモ / Photos / メッセージ / メール（外部 IMAP）/ マイページ
- 入出金・路線・Map・音楽・動画・グループ（契約でオン）
- バックアップ方針の説明と、運営側での取得確認（頻度は契約書に明記）
- 月次の軽微アップデート（セキュリティパッチ・合意した機能）

### 含まれない（標準外・別見積）

- Travel（Travelpayouts）・写真鮮明化・DeepL／LLM 音声の「使い放題」
- 顧客の既存システムからの大規模データ移行
- 24時間電話サポート、オンサイト対応
- 顧客社内の端末キッティング
- Stripe 等の自動課金画面（請求書運用が標準）

### ロールの渡し方

| ロール | 誰に渡すか |
|---|---|
| **SuperAdmin** | 運営のみ（グローバルキー・試作機能） |
| **Admin** | 顧客の契約代表（ユーザー管理・祝日・表示メニュー） |
| **Standard / Light** | 一般利用者 |

インフラの API キー（R2 / DeepL / LiveKit 等）は **SuperAdmin のみ**編集可。顧客 Admin は触れない。

## 4. ストレージと API（BYOK 推奨）

### 推奨: 顧客持ちキー（BYOK）

顧客の Cloudflare R2（または B2）を設定画面（運営 SuperAdmin）で接続する。

- 写真・動画の従量は顧客クラウド請求へ
- 運営の原価リスクが下がる
- 無料枠表示（20GB / Standard 100GB）は「製品上の目安」。BYOK 時は顧客と「上限の見せ方」を合意する

### 代替: 運営共有ストレージ

小規模・検証向けのみ。原価は運営負担になるため、月額にストレージ見合いを上乗せするか、容量上限を契約で厳しくする。

### DeepL / LLM / Maps

- 初版は **オフまたは運営検証のみ**
- 顧客が使うなら BYOK（顧客キー）か、別アドオン契約
- Maps は顧客 Google Cloud プロジェクト＋リファラ制限を推奨

## 5. 構築チェックリスト（納品前）

### インフラ

- [ ] ホスティング／VPS または顧客指定環境
- [ ] ドメイン DNS・SSL
- [ ] `.env`（`APP_URL`、DB、メール、セッション）
- [ ] `php artisan migrate --force`
- [ ] `composer install --no-dev`
- [ ] cron（リマインダ・必要なら写真アーカイブ）
- [ ] バックアップ（DB＋必要ならオブジェクト）の初回確認

### アプリ初期設定

- [ ] SuperAdmin（運営）作成。既知パスワード Seeder は使わない
- [ ] 顧客 Admin 作成・招待コード設定（自己登録を閉じるか招待制）
- [ ] ストレージ接続テスト（R2/B2）
- [ ] Travel を顧客メニューから外す（方針どおり。必要な場合のみ個別付与）
- [ ] 鮮明化・翻訳・LLM は SuperAdmin のみのまま確認
- [ ] 利用規約・プライバシーのリンク表示確認

### 引き渡し

- [ ] Admin ログイン手順・パスワード再設定手順
- [ ] マイページ「プラン・容量」の見方
- [ ] メール申請（有料オプション時）の流れ
- [ ] 障害連絡先・対応時間
- [ ] 請求サイクル・振込先

## 6. 契約・請求の型

### 請求

- 初期: 着手金または完了時一括（推奨: 着手 50% / 公開時 50%）
- 保守: 毎月または年一括（前払い）
- メールボックス: 月次または年次。入金確認後に管理画面で「メールボックス有料オプション」をオン → 申請承認

### 契約に必ず書くこと

1. データ所有者は顧客。解約時のデータエクスポート／削除の期限（例: 解約後30日）
2. BYOK の場合、クラウド利用料は顧客負担
3. 対応時間（例: 平日 10:00–18:00、翌営業日一次回答）
4. 含まれない機能リスト（鮮明化・Travel・使い放題 API）
5. 不可抗力・バックアップの最善努力の範囲

規約・プライバシーはアプリ既存ページをベースに、販売前は弁護士レビュー推奨。

## 8. 最初の1社の進め方

1. 本ファイルの価格で口頭またはメール見積
2. 着手金入金 → 構築チェックリスト実行
3. 顧客 Admin に引き渡し → 残金
4. 翌月から保守請求
5. メールが必要ならオプションを別契約

コード追加は原則不要。現行 `main` をそのままデプロイする。

見積の画面プレビュー（運営 SuperAdmin）: `/admin/sales/estimate`  
条件を変えて印刷できる。単価は `config/commercial.php`。

## 9. 共有インスタンス（販路 B）との切り分け

| | 専用（A） | 共有（B） |
|---|---|---|
| 顧客に Admin | 渡す | **渡さない** |
| ストレージ | BYOK 推奨 | 運営共有＋クォータ |
| 課金 | 請求書 | 将来 Stripe |
| Travel / 鮮明化 | 原則オフ | オフ |

A を売っている間に B の Stripe を急ぐ必要はない。
